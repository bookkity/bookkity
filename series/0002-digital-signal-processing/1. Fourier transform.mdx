# Introduction

The Fourier transform is one of the most important mathematical tools in modern science and engineering. Its main purpose is to take a complicated real-world signal and decompose it into fundamental building blocks that can then be analyzed much more easily.

The discrete Fourier transform (DFT) and closely related transforms, such as the short-time Fourier transform (STFT) and discrete cosine transform (DCT), have applications ranging from audio and image processing and compression (MP3, Opus, Vorbis, etc.) to telecommunication (OFDM/OFDMA in Wi-Fi, 5G NR, LTE), medical imaging (MRI), astronomy (radio interferometry), and many other fields.

# Discrete Fourier transform

Unfortunately, computing the discrete Fourier transform directly is computationally expensive, especially for large input signals.

We can see why by taking a look at its definition.
$$
X_k = \sum_{m = 0}^{N - 1} x_m e^{-i 2\pi \frac{km}{N}}
$$

To compute the full discrete Fourier transform, we need $O(N^2)$ operations. As we can see in the table below, a buffer containing 32,768 samples already requires over one billion summation terms. That's not even a full second of audio at 48 kHz!

|     Input size ($N$) | Operations ($N^2$) |
| -------------------: | -----------------: |
|           $2^5 = 32$ |              1,024 |
|          $2^7 = 128$ |             16,384 |
|          $2^9 = 512$ |            262,144 |
|     $2^{11} = 2,048$ |          4,194,304 |
|     $2^{13} = 8,192$ |         67,108,864 |
|    $2^{15} = 32,768$ |      1,073,741,824 |
|   $2^{17} = 131,072$ |     17,179,869,184 |
|   $2^{19} = 524,288$ |    274,877,906,944 |
| $2^{20} = 1,048,576$ |  1,099,511,627,776 |

Modern computers are powerful, but not that powerful. On my CPU, computing the discrete Fourier transform of a single buffer containing 2,048 elements takes roughly 33 ms using the implementation below. At a sampling rate of 48 kHz, those 2,048 samples represent approximately 42.7 ms of audio. This leaves very little headroom for any other processing, making real-time applications impractical with this approach.

```rs
pub fn naive_discrete_fourier_transform(input: &[Complex], output: &mut [Complex]) {
    assert!(input.len() == output.len());

    let n = input.len();

    for k in 0..n {
        let mut sum = Complex::ZERO;

        for m in 0..n {
            let angle = -2.0 * PI * (k * m) as f32 / n as f32;
            let twiddle = Complex::new(angle.cos(), angle.sin());

            sum += twiddle * input[m];
        }

        output[k] = sum;
    }
}
```

Obviously, we could manually vectorize the code and try to make it as CPU-friendly as possible, but that wouldn't fundamentally change much. Even a highly optimized implementation would still struggle with real-time processing of moderately sized buffers.

Fortunately, as the need arose, clever mathematicians and engineers came up with much more efficient approaches. These approaches are collectively known as the Fast Fourier Transform (FFT). We'll start by looking at the so-called Cooley–Tukey algorithm.

# The Cooley-Tukey algorithm

The algorithm was generalized and popularized by James W. Cooley and John W. Tukey in their 1965 paper, but, as it turns out, its origins go back much further. Carl Friedrich Gauss had already derived a similar algorithm in an unpublished manuscript from 1805, predating even Joseph Fourier's work on Fourier series. Although Gauss's manuscript was eventually published posthumously, his algorithm remained largely unknown for many years.

Other mathematicians independently developed algorithms based on similar principles, including Carl Runge in 1903 and Danielson and Lanczos in 1942.

We will embark on a journey similar to them. 

Let's take another look at the definition and see if anything interesting catches our eye: 
$$
X_k = \sum_{m = 0}^{N - 1} x_m e^{-i 2\pi \frac{km}{N}}
$$

If we're familiar with linear algebra, we might recognize this as a dot product between the input vector $x_m$ and a vector of complex exponentials $e^{-i 2\pi \frac{km}{N}}$. Stricly speaking, the complex inner product involves complex conjugation. Depending on the convention we use, either vector can be conjugated, although it's most common to conjugate the second one. In our case, that would turn $e^{-i 2\pi \frac{km}{N}}$ into $e^{i 2\pi \frac{km}{N}}$. However, this distinction isn't particularly important for what we're trying to accomplish, so we'll ignore it and treat the expression as an ordinary dot product for simplicity.

In vector notation, we can write it as follows:
$$
X_k = \begin{bmatrix} x_0 & x_1 & \dots & x_{N - 1} \end{bmatrix} \cdot \begin{bmatrix} 1 \\ e^{-i 2\pi k/N} \\ \vdots \\ e^{-i 2\pi k(N - 1) / N} \end{bmatrix}
$$

If we've ever taken the time to understand linear algebra intuitively, we might recognize that this equation measures how closely our signal aligns with a particular test function.

That's it. The Fourier transform, both discrete and continuous, is essentially a procedure that compares a signal against a family of test functions and tells us how strongly each one is represented in the original signal.

There's also another way to look at it. If we've worked with complex numbers or are familiar with Euler's formula,
$$
e^{ix} = cos(x) + i sin(x)
$$
we might recognize that we're multiplying our signal by a rotating complex exponential.

In a sense, we're finding the balance point of all these rotating vectors. If they point in roughly the same direction, they reinforce each other. If they point in different directions, they tend to cancel each other out. This also explains why certain frequencies produce large DFT coefficients while others produce values close to zero. 

To come up with an efficient algorithm, we'll have to focus on the exponential part of the equation. We don't want to make any assumptions about the input signal, as that could make our algorithm unreliable in certain real-world scenarios.

Let's try to plot $e^{-i 2\pi \frac{km}{N}}$ for different integer values of $km$, using $N = 8$, and see what happens. 

![[roots-of-unity.svg]]

We got a circle! These points are called the _roots of unity_. More specifically, they are the solutions to the polynomial equation $z^N - 1 = 0$.

If we're familiar with complex numbers, we'll probably recognize that multiplication by $i$ rotates a point in the complex plane by 90 degrees counterclockwise.
A similar thing happens with the roots of unity. Multiplying by $\omega = e^{-i \frac{2\pi}{N}}$ rotates a point clockwise from one root of unity to the next.

With that in mind, we can observe two important properties:
- First, for an even $N$, rotating $\frac{N}{2}$ times takes us to the exact opposite side of the unit circle, In other words, we only need to consider half of the roots of unity; the other half are simply their negatives. This is called half-period symmetry or opposite-root property.
$$\omega^{k + N / 2} = -\omega^k$$
- Second, rotating $N$ times brings us right back to where we started. After all, that's a full 360-degree rotation, which leaves the point unchanged. This is called periodicity.
$$\omega^{k + N} = \omega^k$$

I feel like we should now come back to the original DFT equation and confirm whether the patterns we have seen in our 8-point DFT example are actually there and are transferable or is it simply a coincidence that only occurs for some small DFTs, in particular for our 8-point DFT.

Let's take another peek at the definition and remind ourselves how it looks like:
$$
X_k = \sum_{m = 0}^{N - 1} x_m e^{-i 2\pi \frac{km}{N}}
$$

We have previously introduced $W_N = e^{-i 2\pi \frac{1}{N}}$, but I will not be using it at the very beginning of what we are about to do, because it slightly obscures the most important property.

Let's try to apply our visual intuition and split the sum into two smaller sums one for even elements and one for odd. 

$$
\begin{align}
	X_k &= \sum_{m = 0}^{N - 1}           x_m        e^{-i 2\pi \frac{km}{N}} \\
		  &= \sum_{r = 0}^{\frac{N}{2} - 1} x_{2r}     e^{-i 2\pi \frac{k2r}{N}} 
		   + \sum_{r = 0}^{\frac{N}{2} - 1} x_{2r + 1} e^{-i 2\pi \frac{k(2r + 1)}{N}}
\end{align}
$$

Now, $e^{-i 2\pi \frac{k(2r + 1)}{N}}$ is very close to $e^{-i 2\pi \frac{k2r}{N}}$, we can make both sums share a coefficient by simply splitting $e^{-i 2\pi \frac{k(2r + 1)}{N}} = e^{-i 2\pi \frac{k}{N}} e^{-i 2\pi \frac{k2r}{N}}$, which also allows us to take a common term out of the second sum.

$$
X_k = \sum_{r = 0}^{\frac{N}{2} - 1} x_{2r} e^{-i 2\pi \frac{k2r}{N}} 
    + e^{-i 2\pi \frac{k}{N}} \sum_{r = 0}^{\frac{N}{2} - 1} x_{2r + 1} e^{-i 2\pi \frac{k2r}{N}}
$$

Now comes the second most important observation. Notice that the exponent contains $2kr / N$. We can rewrite this as $kr / (N / 2)$, which means we're actually dealing with the roots of unity for a transform of half the original size. In other words:
$$
W_N^{2r} = W_{N / 2}^r
$$ 

$$
X_k = \sum_{r = 0}^{\frac{N}{2} - 1} x_{2r} W_{N / 2}^{kr} 
    + W_N^k \sum_{r = 0}^{\frac{N}{2} - 1} x_{2r + 1} W_{N / 2}^{kr}
$$

Are you seeing what I'm seeing? We have just proven that computing an $N$-point DFT is equal to computing two $\frac{N}{2}$-point DFTs and summing them together (as long as $N$ is divisible by $2$). 

But there's still more structure to uncover. Do you remember what we saw visually? It seems like the lower half of the even elements is equal to the upper half, while the lower half of the odd elements is the negative of the upper half. Let's see if we can get the equations to agree with us. Before we do that though, let's introduce a new variable $M = \frac{N}{2}$ as that will simplify our equations a little bit. The equation from before becomes:
$$
X_k = \sum_{r = 0}^{M - 1} x_{2r} W_M^{kr} 
    + W_N^k \sum_{r = 0}^{M - 1} x_{2r + 1} W_M^{kr}
$$
Let's also name both sums as that will become useful in a short while.

$$
X_k = \underbrace{\sum_{r = 0}^{M - 1} x_{2r} W_M^{kr}}_{E_k} 
    + W_N^k \underbrace{\sum_{r = 0}^{M - 1} x_{2r + 1} W_M^{kr}}_{O_k}
$$

With that out of the way, we can try to compute $X_{k + M}$ and see where that takes us.

$$
X_{k + M} = \sum_{r = 0}^{M - 1} x_{2r} W_M^{(k + M)r} 
          + W_N^{k + M} \sum_{r = 0}^{M - 1} x_{2r + 1} W_M^{(k + M)r}
$$

Remember, $M$ is half of $N$. which means $W_M^{(k + M)r}$ is a 360 degree rotation in $W_M$, it's $W_M^{(k + M)r} = W_M^{kr}$ due to periodicity. On the other hand, in $W_N$ it's only half a rotation, which means it changes the sign. Hence $W_N^{k + M} = -W_N^k$. 

Thus we get:
$$
X_{k + M} = \sum_{r = 0}^{M - 1} x_{2r} W_M^{kr} 
          - W_N^k \sum_{r = 0}^{M - 1} x_{2r + 1} W_M^{kr}
$$

Combining $X_{k + M}$ with $X_k$, we confirm the symmetry we though we saw visually:
$$
\begin{align}
	X_k       &= E_k + W_N^k O_k \\
	X_{k + M} &= E_k - W_N^k O_k
\end{align}
$$
for $0 \le k \lt M$.

This is another great simplification. With both of those results, we have an algorithm for computing bigger DFTs by breaking them recursively into smaller ones. We can also compute both halves of the output using the same intermediate values, avoiding redundant calculations.

Let's see how optimal exactly is our algorithm. 

The recurrence for this exact operation we've been studying until now is $T(N) = 2T(N / 2) + O(N)$ which using [Master Theorem](https://en.wikipedia.org/wiki/Master_theorem_(analysis_of_algorithms)) gives us $T(N) = O(N \log_2 N)$. This is not very hard to prove without using Master Theorem, but I don't find much pedagogical value in doing so. Moving on. The algorithm we found is $O(N \log_2 N)$, as opposed to the original, naive one, which was $O(N^2)$. Let's take the table from earlier and compare.

|     Input size ($N$) | Operations ($N^2$) | Operations ($N \log_2 N$) |
| -------------------: | -----------------: | ------------------------- |
|           $2^5 = 32$ |              1,024 | 160                       |
|          $2^7 = 128$ |             16,384 | 896                       |
|          $2^9 = 512$ |            262,144 | 4608                      |
|     $2^{11} = 2,048$ |          4,194,304 | 22,528                    |
|     $2^{13} = 8,192$ |         67,108,864 | 106,496                   |
|    $2^{15} = 32,768$ |      1,073,741,824 | 491,520                   |
|   $2^{17} = 131,072$ |     17,179,869,184 | 2,228,224                 |
|   $2^{19} = 524,288$ |    274,877,906,944 | 9,961,472                 |
| $2^{20} = 1,048,576$ |  1,099,511,627,776 | 20,971,520                |

That's an astronomical difference. At least on paper, Cooley-Tukey FFT of approximately 63 seconds at 48 kHz has roughly the same performance as a naive DFT of roughly 0.7 second. 

It's important to note that what we've derived so far isn't the entire Cooley–Tukey algorithm. We've been dealing with a particular variant known as **radix-2 Cooley–Tukey**.

As the name suggests, radix-2 means that we're repeatedly splitting our transform into two smaller transforms. If we want to apply this decomposition all the way down to individual elements, our buffer length must be a power of two.

Fortunately, Cooley–Tukey isn't limited to radix-2. We can use other radices as well, such as radix-3, radix-4, radix-5, and so forth. We can even combine different radices within a single transform. For example, we could first split a transform using radix-7, then radix-5, and finally radix-2. This is known as **mixed-radix Cooley–Tukey**.

In practice, however, FFT implementations usually support only a limited number of radices, since each one requires its own specialized implementation. This means that transforms containing large prime factors can become problematic. A prime-sized transform, in particular, cannot be decomposed into smaller nontrivial transforms using Cooley–Tukey alone.

Fortunately, there are other algorithms that can handle these cases and we'll explore them next.
